Developer Section

This section contains the full source files and technical reference for the Synergy Website scroll animation system. All code is modelled on the motion patterns observed on formcarry.com.

Formcarry.com Motion Analysis

The following patterns were observed and catalogued from formcarry.com to inform the animation system:

Element Type Animation Style Details
Headings / Paragraphs fade-up translateY 36px + opacity 0→1, fired at ~12% viewport
Cards / Feature blocks scale-in scale 0.92→1, ~80ms stagger between siblings
Bold hero text clip-up clip-path inset reveal, bottom-to-top curtain lift
Feature spotlights / Images blur-in blur 8px→0 + slight scale 1.03→1
Easing Spring-like cubic-bezier(0.16, 1, 0.3, 1)
Trigger point 12% visible rootMargin -40px at bottom
Fire-once Yes No replay on scroll-up
Parallax None No parallax or scroll-linked effects observed
Exit animations None Clean entrance-only — no section exit animations

CSS File — animations.css

Paste this into Elementor > Custom CSS or your child theme's style.css. See the User Guide (Section 3) for full instructions.

/* === ANIMATIONS.CSS === */
/* Synergy Website — Scroll Animation System v1.0      */
/* Modelled on formcarry.com motion patterns:          */
/*   • fade-up on headings, paragraphs, cards          */
/*   • scale-in on images / screenshots                */
/*   • blur-in on feature blocks                       */
/*   • clip-up on bold headline reveals                */
/*   • stagger ~80 ms between sibling cards            */
/*   • trigger at ~12 % of element visible             */
/*   • spring-like ease, fire-once                     */
/* --------------------------------------------------- */


/* ================================================================
   1. CUSTOM PROPERTIES
   Change these two values to adjust all speeds site-wide:
     --sg-duration : how long each animation takes  (default 0.65s)
     --sg-ease     : the acceleration curve (leave as-is for best look)
     --sg-distance : how far elements travel before landing (default 36px)
   ================================================================ */
:root {
  --sg-duration:   0.65s;
  --sg-ease:       cubic-bezier(0.16, 1, 0.3, 1);   /* spring-like ease-out */
  --sg-distance:   36px;
}


/* ================================================================
   2. ACCESSIBILITY — REDUCED MOTION
   If the visitor's OS has "Reduce Motion" turned on, we skip ALL
   animations and show every element immediately.
   ================================================================ */
@media (prefers-reduced-motion: reduce) {
  [data-animate],
  [data-animate-group] > * {
    opacity:    1 !important;
    transform:  none !important;
    filter:     none !important;
    clip-path:  none !important;
    transition: none !important;
    animation:  none !important;
  }
}


/* ================================================================
   3. BASE HIDDEN STATE
   Every element tagged with data-animate starts invisible.
   JS will add .is-visible to trigger the transition.
   ================================================================ */
[data-animate] {
  opacity: 0;

  /* Transition all animatable properties in one declaration.
     --sg-delay is set by JS for staggered groups, or via
     data-animate-delay="200" on individual elements.           */
  transition:
    opacity   var(--sg-duration) var(--sg-ease),
    transform var(--sg-duration) var(--sg-ease),
    filter    var(--sg-duration) var(--sg-ease),
    clip-path var(--sg-duration) var(--sg-ease);

  transition-delay: var(--sg-delay, 0ms);
}


/* ================================================================
   4. PER-ANIMATION INITIAL TRANSFORMS
   Only opacity + transform + filter are animated — never width /
   height / top / left / margin — to keep every animation on the
   GPU compositor layer and avoid layout recalc.
   ================================================================ */

/* Slide up from below (most common — headings, paragraphs, cards) */
[data-animate="fade-up"] {
  transform: translateY(var(--sg-distance));
}

/* Slide in from the right (e.g. right-side feature text) */
[data-animate="fade-left"] {
  transform: translateX(var(--sg-distance));
}

/* Slide in from the left (e.g. left-side feature text) */
[data-animate="fade-right"] {
  transform: translateX(calc(-1 * var(--sg-distance)));
}

/* Grow in from centre (images, UI screenshots, icon blocks) */
[data-animate="scale-in"] {
  transform: scale(0.92);
}

/* Soft blur to sharp (hero text, feature spotlights) */
[data-animate="blur-in"] {
  filter:    blur(8px);
  transform: scale(1.03);
}

/* Curtain-lift / clip reveal (bold headlines, dividers) */
[data-animate="clip-up"] {
  clip-path: inset(0 0 100% 0);
  transform: translateY(12px);
}


/* ================================================================
   5. VISIBLE STATE
   JS adds .is-visible when the element enters the viewport.
   All animated properties return to their natural (resting) values.
   ================================================================ */
[data-animate].is-visible {
  opacity:   1;
  transform: none;
  filter:    none;
  clip-path: inset(0% 0 0 0);
}

JavaScript File — animations.js

Paste this into Elementor > Custom Code (Pro) or your theme's functions.php via the PHP wrapper below. See the User Guide (Section 4) for full instructions.

/* === ANIMATIONS.JS === */
/* Synergy Website — Scroll Animation Engine v1.0      */
/* Vanilla JS · Zero dependencies · ~2.1 KB            */
/*                                                     */
/* Trigger: data-animate="fade-up|fade-left|fade-right */
/*          |scale-in|blur-in|clip-up"                 */
/* Group:   data-animate-group  (staggers children)    */
/* Delay:   data-animate-delay="200"  (ms override)    */
/* Repeat:  data-animate-once="false" (re-fires)       */
/* ---------------------------------------------------  */

(function () {
  'use strict';

  /* ----------------------------------------------------------
     0. BAIL EARLY for users who prefer reduced motion.
        Elements are already visible via the CSS @media rule;
        we just skip all JS setup entirely.
     ---------------------------------------------------------- */
  if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;


  /* ----------------------------------------------------------
     1. CONFIGURATION
        threshold  : fraction of element that must be visible
                     before the animation fires (0.12 = 12 %)
        rootMargin : virtual padding on the viewport boundary.
                     "-40px" at the bottom means the trigger
                     fires 40 px before the element's bottom
                     edge reaches the viewport bottom.
     ---------------------------------------------------------- */
  var STAGGER_STEP = 80;   /* ms added per sibling in a group */
  var IO_OPTIONS   = {
    threshold:  0.12,
    rootMargin: '0px 0px -40px 0px'
  };


  /* ----------------------------------------------------------
     2. SINGLE SHARED IntersectionObserver
        One instance watches every [data-animate] on the page.
     ---------------------------------------------------------- */
  var observer = new IntersectionObserver(onIntersect, IO_OPTIONS);


  /* ----------------------------------------------------------
     3. INTERSECTION CALLBACK
     ---------------------------------------------------------- */
  function onIntersect(entries) {
    entries.forEach(function (entry) {
      if (!entry.isIntersecting) return;

      var el = entry.target;
      revealElement(el);

      /* Fire-once (default): stop watching after first trigger */
      if (el.dataset.animateOnce !== 'false') {
        observer.unobserve(el);
      }
    });
  }


  /* ----------------------------------------------------------
     4. REVEAL ONE ELEMENT
        • Apply will-change just before the animation so the
          browser can promote the layer without repainting the
          whole page.
        • Use rAF to batch class changes and avoid layout thrash.
        • Remove will-change on transitionend to free GPU memory.
     ---------------------------------------------------------- */
  function revealElement(el) {
    el.style.willChange = 'transform, opacity, filter';

    requestAnimationFrame(function () {
      el.classList.add('is-visible');

      el.addEventListener('transitionend', function onDone() {
        el.style.willChange = '';
        el.removeEventListener('transitionend', onDone);
      });
    });
  }


  /* ----------------------------------------------------------
     5. STAGGER A GROUP'S DIRECT CHILDREN
        Called on any element with [data-animate-group].
        • If children already have data-animate → keep their
          animation type, just add incrementing delays.
        • If none have data-animate → auto-apply "fade-up" to
          every direct child, then stagger.
        • Respects each child's own data-animate-delay as a
          base offset (stagger is added on top of it).
     ---------------------------------------------------------- */
  function staggerGroup(parent) {
    /* Guard: skip if already processed (prevents double-run) */
    if (parent.dataset.animateGroupDone) return;
    parent.dataset.animateGroupDone = '1';

    var children = Array.prototype.slice.call(parent.children);

    /* Targets = children that already carry data-animate */
    var targets = children.filter(function (c) {
      return c.hasAttribute('data-animate');
    });

    /* If none have the attribute, auto-apply fade-up to all */
    if (targets.length === 0) {
      targets = children;
      targets.forEach(function (c) {
        if (!c.hasAttribute('data-animate')) {
          c.setAttribute('data-animate', 'fade-up');
        }
      });
    }

    targets.forEach(function (c, i) {
      var base  = parseInt(c.dataset.animateDelay || 0, 10);
      var delay = base + i * STAGGER_STEP;
      c.style.setProperty('--sg-delay', delay + 'ms');
    });
  }


  /* ----------------------------------------------------------
     6. REGISTER ELEMENTS INSIDE A ROOT NODE
        • Processes groups first so stagger delays are written
          to CSS custom properties before the observer fires.
        • Guards against double-registration with a data flag.
     ---------------------------------------------------------- */
  function registerElements(root) {
    root = root || document;

    /* 6a. Stagger all groups */
    root.querySelectorAll('[data-animate-group]').forEach(function (group) {
      staggerGroup(group);
    });

    /* 6b. Observe every [data-animate] element */
    root.querySelectorAll('[data-animate]').forEach(function (el) {
      /* Skip already-registered elements */
      if (el.dataset.animateRegistered) return;
      el.dataset.animateRegistered = '1';

      /* Apply individual delay for non-group elements */
      if (el.dataset.animateDelay && !el.closest('[data-animate-group]')) {
        el.style.setProperty('--sg-delay', el.dataset.animateDelay + 'ms');
      }

      observer.observe(el);
    });
  }


  /* ----------------------------------------------------------
     7. MUTATIONOBSERVER — Elementor lazy-load fallback
        Elementor can inject new .elementor-section nodes into
        the DOM after initial page load (e.g. infinite scroll,
        popup builders, lazy-render sections).
        This watcher picks up any new [data-animate] elements
        injected after init() has already run.
     ---------------------------------------------------------- */
  var mutObs = new MutationObserver(function (mutations) {
    mutations.forEach(function (m) {
      m.addedNodes.forEach(function (node) {
        if (node.nodeType !== 1) return; /* ignore text nodes */

        /* New node itself might be animated */
        if (node.hasAttribute && node.hasAttribute('data-animate')) {
          if (!node.dataset.animateRegistered) {
            node.dataset.animateRegistered = '1';
            if (node.dataset.animateDelay && !node.closest('[data-animate-group]')) {
              node.style.setProperty('--sg-delay', node.dataset.animateDelay + 'ms');
            }
            observer.observe(node);
          }
        }

        /* New node may contain animated children */
        if (node.querySelectorAll) {
          node.querySelectorAll('[data-animate-group]').forEach(function (g) {
            staggerGroup(g);
          });
          node.querySelectorAll('[data-animate]').forEach(function (el) {
            if (el.dataset.animateRegistered) return;
            el.dataset.animateRegistered = '1';
            if (el.dataset.animateDelay && !el.closest('[data-animate-group]')) {
              el.style.setProperty('--sg-delay', el.dataset.animateDelay + 'ms');
            }
            observer.observe(el);
          });
        }
      });
    });
  });


  /* ----------------------------------------------------------
     8. BOOT SEQUENCE
        • Runs on DOMContentLoaded (or immediately if DOM is
          already ready — handles Footer JS placement).
        • Also listens for Elementor's own "frontend init" event
          which fires after Elementor re-renders widgets.
        • MutationObserver watches for any further DOM changes.
     ---------------------------------------------------------- */
  function init() {
    registerElements(document);
    mutObs.observe(document.body, { childList: true, subtree: true });
  }

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', init);
  } else {
    /* DOM already parsed (script is in footer) */
    init();
  }

  /* Elementor fires this after its frontend module bootstraps */
  window.addEventListener('elementor/frontend/init', function () {
    registerElements(document);
  });

}());

Developer Quick Guide

Attributes API

Attribute Value(s) Description
data-animate fade-up Slides element up from 36px below + fades in. Most common — use on headings, paragraphs, and cards.
data-animate fade-left Slides element in from the right side. Use on right-column feature text.
data-animate fade-right Slides element in from the left side. Use on left-column feature text.
data-animate scale-in Grows element from scale 0.92 to 1. Use on images, UI screenshots, and icon blocks.
data-animate blur-in Transitions from blur(8px) to sharp + slight scale. Use on hero text and feature spotlights.
data-animate clip-up Curtain-lift clip-path reveal from bottom to top. Use on bold headlines and dividers.
data-animate-group (no value needed) Place on a parent/section element. All direct children with data-animate will be staggered at 80ms intervals. If no children have data-animate, fade-up is auto-applied to all direct children.
data-animate-delay Number (ms), e.g. 200 Overrides or adds to the stagger delay for a single element. E.g. data-animate-delay="400" waits 400ms before animating.
data-animate-once false By default, animations fire once and stop. Set this to false to re-fire the animation every time the element re-enters the viewport on scroll-up/scroll-down.

How to Add Attributes in Elementor

  1. Click the element in the Elementor editor to select it.
  2. Open the Advanced tab in the left panel.
  3. Scroll down to Custom Attributes.
  4. Click + Add Row.
  5. In the Key field enter: data-animate
  6. In the Value field enter: fade-up (or whichever animation you want)
  7. Click Update to save.

To add a delay, add another row: Key = data-animate-delay, Value = 200 (milliseconds).

To add a group, select the parent section/container and add: Key = data-animate-group, Value = (leave empty, or enter any value — the presence of the attribute is what matters).

Timing Customisation

All animation timing is controlled by three variables. Change them once and every animation on the site updates automatically:

  • Duration: Edit --sg-duration in the CSS :root block. Default: 0.65s.
  • Distance: Edit --sg-distance in the CSS :root block. Default: 36px.
  • Easing: Edit --sg-ease in the CSS :root block. Default: cubic-bezier(0.16, 1, 0.3, 1) (spring-like).
  • Stagger step: Edit STAGGER_STEP = 80 in animations.js. Default: 80 ms between siblings.

Observer Settings

The IntersectionObserver is configured with two key values in animations.js:

  • threshold: 0.12 — 12% of the element must be visible in the viewport before the animation fires. Lower values fire earlier; higher values fire later.
  • rootMargin: '0px 0px -40px 0px' — Shrinks the effective viewport by 40px at the bottom. This means the animation fires only when the element is at least 40px inside the visible area, preventing immediate triggers on elements that are just barely below the fold.

Performance Checklist

  • ✅ Only GPU-compositable properties are animated (transform, opacity, filter, clip-path) — no width, height, top, left, or margin changes that cause layout recalc.
  • ✅ will-change is applied immediately before each animation and removed on transitionend — no permanent GPU layer promotion.
  • ✅ A single shared IntersectionObserver instance watches all elements — no per-element observers.
  • ✅ Fire-once by default — observer unregisters each element after first trigger, reducing active watchers over time.
  • ✅ Reduced-motion users receive a complete CSS bail-out and JS bail-out — zero animation overhead.
  • ✅ requestAnimationFrame is used to batch DOM class changes and avoid layout thrash.
  • ✅ Zero external dependencies — no jQuery, no GSAP, no ScrollReveal — the full engine is ~2.1 KB.

User Guide

This section is written for the site owner or content manager. No coding knowledge is required. Follow each section in order the first time you set this up.

Section 1 — What are scroll animations and what will change on your site

The "unrolling newspaper" analogy

Imagine your website is a newspaper. Without scroll animations, the entire page appears fully printed the moment someone opens it — every headline, image, and paragraph is already sitting there waiting. With scroll animations, the newspaper unrolls itself as the reader moves down the page. Each section reveals itself at the right moment, drawing the eye forward and making the content feel alive and intentional.

What your visitors will see

After the system is installed and configured, elements on your pages will animate in as visitors scroll down:

  • Headings will gently slide up from slightly below their final position and fade into view.
  • Paragraphs will fade in with the same smooth upward movement.
  • Cards and feature blocks in rows will cascade in one after another — the first card appears, then 80 milliseconds later the second, then the third — creating a flowing, rhythmic reveal.
  • Images and screenshots will grow from 92% of their size to full size, giving a subtle "settling into place" effect.
  • Bold hero headlines can use a curtain-lift effect where the text appears to rise up from behind a hidden barrier.

All animations are quick — the default duration is 0.65 seconds — and use a spring-like easing curve that feels natural rather than mechanical.

Why it makes your site feel premium

Think about a premium shop: when you push the door open, the lights are bright, the displays are arranged with care, and you feel welcomed. A site without animations is like a shop where all the stock is piled on the floor the moment you walk in. Scroll animations act like a well-trained shop assistant who presents each item to you at exactly the right moment. The content feels curated, not dumped. This is why high-end SaaS products, agencies, and premium brands consistently use this technique.

What this system does NOT do

  • It does not change any of your content, fonts, colours, or layouts.
  • It does not slow down your site — the code is under 2.1 KB with zero external dependencies, and animations only run on the GPU, which is separate from the CPU that loads page content.
  • It does not affect visitors who have "Reduce Motion" turned on in their device's accessibility settings. Those users will see all content immediately with no animation whatsoever.
  • It does not affect your SEO — search engine crawlers do not render animations.
  • It does not add any scroll-linked parallax effects — everything is purely entrance-based.

Section 2 — Before you start: a safety checklist

Before making any changes to your website's code, complete this checklist. These steps protect your site from accidental breakage.

  1. Back up the entire site.

    Use a plugin such as UpdraftPlus (free) or your hosting provider's backup feature. After the backup completes, download the backup file to your computer. Do not rely solely on a cloud backup — keep a local copy too.

    ⚠️ Watch out: Do this every single time before you make any code changes, even small ones. It takes two minutes and can save hours of recovery work.
  2. Check whether you have Elementor Free or Elementor Pro.

    Go to your WordPress dashboard, then Elementor > Settings. If you can see a Custom Code tab, you have Elementor Pro. If you do not see that tab, you have Elementor Free. This matters because the JavaScript installation method differs between the two versions.

  3. Use a staging environment if available.

    A staging environment is a private copy of your website that is invisible to the public — like a dress rehearsal before opening night. Any changes you make on staging have no effect on the live site. Your hosting provider may offer one-click staging (common with WP Engine, Kinsta, SiteGround, and Cloudways). If staging is available, make all the changes described in this guide on staging first, verify everything works, and only then repeat the steps on the live site.

    If staging is not available, that is fine — proceed directly, but be extra careful and make sure your backup is complete before you start.

Section 3 — Installing the CSS

The CSS file defines what each animation looks like and sets the default speeds and distances. You must install the CSS before the JavaScript, or elements will become permanently invisible when the JS runs.

Option A — Recommended: Elementor Custom CSS

  1. In your WordPress dashboard, go to Elementor > Custom CSS.
  2. In the large text area, paste the entire contents of the animations.css code block from the Developer Section above.
  3. Click Save Changes.
✅ How to verify it worked: Open your live site in a browser. Right-click anywhere on the page and choose Inspect (or press F12). In the Styles panel, use the filter/search box and type sg-duration. You should see --sg-duration: 0.65s appear in the results. If you see it, the CSS is loaded correctly.

Option B: Appearance > Theme File Editor > style.css

  1. In your WordPress dashboard, go to Appearance > Theme File Editor.
  2. In the file list on the right, click style.css.
  3. Scroll to the very bottom of the file.
  4. Paste the entire contents of the animations.css code block after all existing code.
  5. Click Update File.
⚠️ Watch out: Only do this in a child theme. If you edit the parent theme's style.css, your changes will be permanently deleted the next time the theme is updated. If you are not sure whether you have a child theme, use Option A instead.

⚠️ Watch out: Always install the CSS (Section 3) before the JavaScript. If you install the JS without the CSS, every element tagged with data-animate will start invisible and never appear — even after you later add the CSS, a hard reload may be needed.

Section 5 — How to apply animations in Elementor

Understanding data attributes — the "sticky note" analogy

A data attribute is like a sticky note attached to an element on your page. The CSS and JavaScript code on your site reads these sticky notes and knows what to do. When you attach a sticky note that says data-animate="fade-up" to a heading, the animation system sees it and knows: "fade this heading up when it enters the screen." You are not writing any code — you are just attaching labels.

Where to find Custom Attributes in Elementor

  1. Click any element in the Elementor editor (e.g. a heading, image, or section) to select it.
  2. Look at the left panel. At the top are three tabs: Content, Style, and Advanced. Click Advanced.
  3. Scroll down in the Advanced panel until you see Custom Attributes.
  4. Click + Add Row. Two fields appear: Key on the left and Value on the right.
  5. Type the attribute name in the Key field and the value in the Value field.

All animation attribute combinations

Key (Attribute Name) Value What it does
data-animate fade-up Element slides up from below and fades in. Best for headings and paragraphs.
data-animate fade-left Element slides in from the right. Best for right-column text blocks.
data-animate fade-right Element slides in from the left. Best for left-column text blocks.
data-animate scale-in Element grows from 92% to full size. Best for images and feature cards.
data-animate blur-in Element transitions from blurry to sharp. Best for hero text and spotlights.
data-animate clip-up Curtain-lift reveal from bottom to top. Best for bold standalone headlines.
data-animate-group (leave empty) Place on a parent section. Children with data-animate will stagger 80ms apart.
data-animate-delay e.g. 200 Adds an extra delay (in ms) before this element's animation fires.
data-animate-once false Makes the animation re-fire every time the element scrolls into view.
data-animate-group + child data-animate (combined) Group on parent + animation on each child = staggered cascade.

  2. Go to the Advanced tab > Custom Attributes > + Add Row.

  4. Click Update.

  6. Go to the Advanced tab > Custom Attributes > + Add Row.
  7. Key: data-animate | Value: fade-up
  8. Add a second row: Key: data-animate-delay | Value: 200
  9. Click Update.

  2. Go to the Advanced tab > Custom Attributes > + Add Row.
  3. Key: data-animate-group | Value: (leave empty)
  4. Click Update.
  5. Click the first card widget.
  6. Go to the Advanced tab > Custom Attributes > + Add Row.
  7. Key: data-animate | Value: scale-in
  8. Click Update.
  9. Repeat steps 5–8 for the second and third cards.
✅ Self-verify: Open the live page and scroll to the card section. Card 1 should appear first, then card 2 appears 80ms later, then card 3 appears 80ms after card 2 — creating a flowing left-to-right cascade. If all three appear simultaneously, check that data-animate-group is on the parent section and not on one of the cards themselves.

Section 6 — Timing and speed

Understanding duration and delay

Duration is how long the animation takes from start to finish. Think of it as the speed of the animation itself. A duration of 0.65 seconds means the animation completes in just over half a second — quick enough to feel snappy but slow enough to be visible and satisfying.

Delay is how long the animation waits before it starts. Think of it as an actor waiting in the wings for their cue. A delay of 200ms means the animation begins 200 milliseconds after the element enters the viewport — enough time for the previous element to have started its entrance, creating a sequential, staged feel rather than everything happening at once.

The CSS custom properties (edit these to change all animations at once)

:root {
  --sg-duration:   0.65s;   /* Change this to speed up or slow down all animations */
  --sg-ease:       cubic-bezier(0.16, 1, 0.3, 1);   /* Leave this as-is for best results */
  --sg-distance:   36px;    /* How far elements travel before landing */
}

The JS stagger step (edit this to change cascade spacing)

var STAGGER_STEP = 80;   /* ms added per sibling in a group */

Common adjustments

Goal Change New Value
Make all animations faster --sg-duration in CSS :root 0.45s
Make all animations slower / more dramatic --sg-duration in CSS :root 0.85s
Elements travel a shorter distance --sg-distance in CSS :root 20px
Elements travel a greater distance --sg-distance in CSS :root 60px
Tighter, faster card cascade STAGGER_STEP in JS 50
Looser, slower card cascade STAGGER_STEP in JS 150
⚠️ Watch out: When making these edits, only change the number (or the unit like s or px). Do not change the variable names, the colons, the semicolons, or anything else in the surrounding code. A single misplaced character in CSS or JS can break the entire system.

Section 7 — Troubleshooting

If something isn't working as expected, find the problem description below and follow the steps.

Problem 1 — Element is invisible / never appears

Symptom: An element you tagged with data-animate starts invisible and never fades in, no matter how far you scroll.

Most likely cause: The JavaScript file is not loaded, so the .is-visible class is never added to the element.

Fix:

  1. Open the live page in a browser and press F12 to open Developer Tools.
  2. Click the Console tab and look for any red error messages. A message like "Uncaught SyntaxError" or "404 (Not Found)" indicates the JS has a problem or isn't loading at all.
  3. Try a hard reload: press Ctrl+Shift+R (Windows/Linux) or Cmd+Shift+R (Mac). This bypasses the browser cache and forces a fresh load.
  4. In Elementor, click the affected element and check the Advanced > Custom Attributes panel. Confirm that the data-animate attribute is saved and spelled correctly (no capital letters, no extra spaces).
  5. If the JS was installed via Elementor Custom Code, confirm the snippet's status is set to Active.

Problem 2 — Animations are choppy on mobile

Symptom: Animations look smooth on a desktop computer but stutter or lag on smartphones.

Cause: The blur-in animation is GPU-intensive. Mobile GPUs struggle with blur transitions, especially on older or mid-range devices.

Fix:

  1. Find any elements using data-animate="blur-in" and change the value to data-animate="fade-up" in their Custom Attributes panel.
  2. If animations still stutter after removing blur, try increasing the duration slightly: change --sg-duration from 0.65s to 0.8s in the CSS. Slower animations are smoother on lower-powered hardware.

Problem 3 — Animations work in the Elementor editor but not on the live site

Symptom: You can see the animation preview inside Elementor, but on the published live site the elements either appear instantly (no animation) or remain invisible.

Cause: A caching plugin or CDN is serving an old version of the page that doesn't include your CSS or JS changes.

Fix:

  1. Clear your WordPress cache plugin (e.g. WP Rocket: Dashboard > Clear Cache; LiteSpeed Cache: LiteSpeed > Purge All; W3 Total Cache: Performance > Purge All Caches).
  2. Clear your browser cache with a hard reload: Ctrl+Shift+R or Cmd+Shift+R.
  3. If you are using a CDN (e.g. Cloudflare), log into your CDN dashboard and purge the cache for the affected URL or purge everything.

Problem 4 — All elements animate simultaneously instead of cascading

Symptom: You added data-animate-group to create a cascade, but all cards animate at exactly the same time.

Most likely cause: The data-animate-group attribute is on one of the child cards instead of the parent section or container.

Fix:

  1. In Elementor, click each card and go to Advanced > Custom Attributes. Remove data-animate-group from any card that has it.
  2. Click the parent section or container that wraps all the cards. Go to Advanced > Custom Attributes and add data-animate-group (with an empty value) there instead.
  3. Click Update and reload the live page.

Problem 5 — White screen after pasting code

Symptom: After saving functions.php (or activating an Elementor Custom Code snippet), the entire site goes blank.

Fix (Elementor Custom Code route):

  1. Navigate to yoursite.com/wp-admin.
  2. Go to Elementor > Custom Code.
  3. Find your scroll animation snippet and change its status from Active to Inactive.
  4. Review the JS code for any syntax errors (a missing closing bracket, an extra quote mark, etc.).

Fix (functions.php route):

  1. Navigate to yoursite.com/wp-admin.
  2. Go to Appearance > Theme File Editor > functions.php.
  3. Remove the code block you added.
  4. Click Update File.
  5. If wp-admin is also unreachable, restore the full site backup you made in Section 2.

Problem 6 — Animation doesn't fire on a lazy-loaded section

Symptom: Most animations work fine, but one section — usually near the bottom of a long page — never animates.

Cause: Elementor sometimes lazy-loads sections that are far down the page, injecting them into the DOM after the animation script has already run its initial setup. The built-in MutationObserver in animations.js is designed to catch these late-arriving elements automatically.

Fix (if the MutationObserver fallback isn't resolving it):

  1. In your WordPress dashboard, go to Elementor > Settings > Advanced.
  2. Try toggling the Optimized DOM Output setting (turn it off if it's on, or on if it's off). This changes how Elementor structures the HTML and can affect when lazy sections are injected.
  3. Alternatively, add data-animate-delay="300" to the element in the problematic section — the extra delay gives Elementor time to finish rendering before the animation fires.

Section 8 — Remove one animation

If you decide you no longer want a specific element to animate, follow these steps to remove just that one animation while leaving the rest of the system intact.

  1. Open the page in Elementor and click the element you want to stop animating.
  2. Go to the Advanced tab in the left panel.
  3. Scroll down to Custom Attributes.
  4. Find the row where the Key is data-animate. Click the minus (−) or delete (×) icon on the right side of that row to remove it.
  5. If there is also a row for data-animate-delay, remove that row too.
  6. If there is also a row for data-animate-once, remove that row too.
  7. If the parent section of this element has data-animate-group and this was the only animated child, consider whether to remove data-animate-group from the parent as well.
  8. Click Update to save your changes.
  9. Open the live page and do a hard reload (Ctrl+Shift+R or Cmd+Shift+R).
✅ The element will now appear immediately when the page loads, with no animation. All other elements on the page will continue to animate as before.

Section 9 — Full uninstall

Follow these steps if you want to completely remove the scroll animation system from your site and return everything to normal.

⚠️ Watch out: You must remove the CSS and JS together. If you remove only the JavaScript and leave the CSS in place, all elements tagged with data-animate will start invisible and never appear — your site content will vanish. Always remove both files.

Step 1 — Remove all data-animate attributes from your pages

This step ensures no elements are left in a permanently-invisible state after the CSS is removed.

  1. Go through each page in Elementor and follow the steps in Section 8 to remove the data-animate attribute (and any data-animate-delay, data-animate-once, and data-animate-group attributes) from every element.
  2. If you have a large number of animated elements, ask your developer to do a database search-replace to remove all instances of these attributes at once.

Step 2 — Remove the JavaScript

  • If installed via Elementor Custom Code: Go to Elementor > Custom Code, find the scroll animation snippet, and click Delete (or set Status to Inactive).
  • If installed via functions.php: Go to Appearance > Theme File Editor > functions.php, find the synergy_add_scroll_animations function block, delete it entirely (from the opening <?php or function line to the closing add_action line), and click Update File.

Step 3 — Remove the CSS

  • If installed via Elementor Custom CSS: Go to Elementor > Custom CSS, find and delete the entire animations block (everything between and including /* === ANIMATIONS.CSS === */ and the final closing brace), and click Save Changes.
  • If installed via style.css: Go to Appearance > Theme File Editor > style.css, find and delete the pasted animation code block, and click Update File.

Step 4 — Clear cache and verify

  1. Clear your WordPress caching plugin (purge all).
  2. Hard-reload each page in your browser (Ctrl+Shift+R or Cmd+Shift+R).
  3. Verify that all page content is visible, no elements are invisible or animated, and the site behaves exactly as it did before the system was installed.
