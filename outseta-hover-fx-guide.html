Outseta Hover FX

Pointer-follow image motion for WordPress + Elementor — a production-safe reusable interaction system derived from live analysis.

WordPress Elementor Vanilla JS No Libraries Accessible

Section 01

Executive Summary

This document is the complete implementation guide for reproducing the pointer-follow image hover motion seen on outseta.com, adapted for a live WordPress + Elementor environment.

What This System Does

When a user moves their cursor over a card component, the image or media element inside the card subtly translates in the direction of the pointer — creating a sense of depth, responsiveness, and refined interactivity. The effect resets smoothly when the cursor leaves.

What You Get

  • One lightweight CSS block (~40 lines) — no framework required
  • One self-initialising JS module (~120 lines) — no jQuery, no GSAP, no libraries
  • An optional PHP snippet to load both safely into WordPress
  • A declarative data-attribute API for Elementor content editors
  • Full accessibility support: prefers-reduced-motion and touch-device fallbacks built in
  • MutationObserver integration so it works with Elementor's dynamic rendering

What Could Be Confirmed

CONFIRMED The task description explicitly states: "image subtly moves in response to cursor hover / pointer movement"
CONFIRMED The provided DOM hint shows a <div class="card-body"> structure containing image/avatar media, surrounding metadata, and nested wrappers
CONFIRMED The word "subtly" in the description places this in the decorative micro-motion category, not a strong 3D tilt

INFERRED The reset uses a smooth CSS transition (cubic-bezier ease-out), not a hard snap

UNCERTAIN Whether rotation (rotateX/rotateY) is applied in addition to translation
UNCERTAIN Whether a box-shadow or pseudo-3D depth layer is added on hover
UNCERTAIN Exact easing curve and transition duration
UNCERTAIN Whether a subtle scale (1.02–1.04) is applied to the image on hover entry

Implementation Approach for Uncertain Areas

Where uncertain, this implementation uses the safest, most common values for this interaction category on modern SaaS marketing sites, and exposes them as configurable data attributes so they can be tuned on the live site without code changes.

Section 03

Interaction Behavior Analysis

Effect Classification

This effect is best classified as a pointer-follow translate with smooth reset — a 2D parallax-lite motion where the image tracks the cursor position relative to the card center, then returns to origin on exit.

PropertyValue / Behavior
Interaction typePointer-follow translate (2D)
Triggerpointermove on outer card wrapper
Moving elementInner image / media element
Translation range±8px X, ±8px Y (configurable)
RotationNone (not used in subtle variant)
ScaleOptional, disabled by default
Motion trackingRelative to card center (normalized -1 to 1)
Smoothing during moveNone — direct RAF update for responsiveness
Reset smoothingCSS transition: 0.6s cubic-bezier(0.23, 1, 0.32, 1)
Performance costMinimal — GPU transform only, RAF-throttled

Motion State Machine

  1. Idle: Image at transform: translate3d(0,0,0)
  2. Pointer enters card: is-tracking class added, transition shortened for responsiveness
  3. Pointer moves across card: RAF callback calculates normalized offset, sets CSS vars, applies transform
  4. Pointer leaves card: CSS vars reset to 0, long transition plays the smooth return to center
  5. Settled: Image back at origin, class removed

Architecture: Why the Image Moves, Not the Card

The outer card wrapper is the pointer target. The inner image is the transform target. This separation gives:

  • Full card hit area for smooth, natural trigger
  • Only the image moves — metadata stays anchored, improving readability
  • Overflow hidden on wrapper contains the slight image overhang
  • No layout shifts — only the composited image layer moves

Section 04

WordPress + Elementor Strategy

Safest DOM Contract

The system attaches via data-hover-fx on the outer wrapper. This means:

  • No dependence on Elementor's generated class names (which change)
  • No dependence on theme CSS specificity
  • Addable via Elementor's Advanced → HTML Attributes panel — no code editing
  • Removable by simply deleting the attribute

Avoiding Conflicts With Existing CSS and JS

Risk: CSS Specificity Conflicts

If existing theme CSS sets transform on elements that also get hover-fx-target, values may conflict. Solution: use the data-hover-fx-target attribute directly on the image element and keep specificity low on our selectors.

Risk: Existing JS Event Listeners

If another plugin or theme JS attaches mousemove to document globally, it could fire alongside this system. Solution: our pointer listeners are scoped to individual card elements — no global event pollution.

Safe Pattern: CSS Custom Properties as Interface

The JS never directly sets transform. It sets --hfx-x and --hfx-y CSS variables on the target element. The CSS reads those variables and builds the transform. This means theme CSS can still override the base transform if needed, and the JS stays independent of CSS specificity.

Handling Elementor Dynamic Rendering

Elementor can re-render widgets on breakpoint switch, in the editor, or when using popup/section triggers. The JS uses a MutationObserver to detect new DOM nodes and re-initialise any [data-hover-fx] elements that appear.

Each host element gets an _hfxInitialized flag to prevent double-binding listeners.

Loading Order

  1. CSS loads in <head> — elements are styled before JS runs
  2. JS loads in footer with defer — does not block render
  3. JS initialises on DOMContentLoaded and also hooks into elementor/frontend/init
  4. If JS never loads, elements display perfectly normally — no broken states

Should This Be CSS-Only?

CSS-only hover translate (:hover { transform: translate(4px, 4px) }) cannot follow the pointer. It can only apply a fixed offset on hover entry. For the specific interaction described — where the image moves with the cursor position — JavaScript is required. However, we include a CSS-only fallback so the experience degrades gracefully.

Section 05

Hover FX Architecture

System Overview

The system has three layers:

Layer 1 — CSS Foundation

Sets will-change: transform, defines the reset transition, reads CSS variables for the transform value, and applies media query guards for reduced motion and touch. This layer is always active.

Layer 2 — JS Engine

Listens for pointermove on [data-hover-fx] hosts. Calculates normalized cursor offset from card center. Sets --hfx-x and --hfx-y on the target element via requestAnimationFrame. Handles entry/exit state.

Layer 3 — Declarative Config

Data attributes on the HTML element configure intensity, scale, and target selector. No JS changes needed to tune the effect on any given element.

Section 07

CSS Code

Add this to: Elementor → Theme Style → Custom CSS, or via the WordPress Customizer under Additional CSS, or via a Code Snippets plugin.

hover-fx-system.css 
/* ============================================================
   HOVER FX SYSTEM v1.0
   Pointer-follow image translate for WordPress + Elementor
   No external dependencies. Drop into custom CSS.
   ============================================================ */

/* ── 1. Accessibility guard ─────────────────────────────── */
/* Hard-disable all motion for users who request it */
@media (prefers-reduced-motion: reduce) {
  .hover-fx-target {
    transition: none !important;
    transform: translate3d(0, 0, 0) !important;
  }
}

/* Hard-disable on touch / no-pointer devices */
@media (hover: none) {
  .hover-fx-target {
    transition: none !important;
    transform: translate3d(0, 0, 0) !important;
  }
}

/* ── 2. Host wrapper ────────────────────────────────────── */
/* The element with data-hover-fx — receives pointer events */
[data-hover-fx] {
  position: relative; /* needed if children are absolute */
  overflow: hidden;   /* clips image overhang at card edges */
}

/* ── 3. Transform target ────────────────────────────────── */
/* The element with class hover-fx-target — this is what moves */
.hover-fx-target {
  /* Hint to browser compositor for smooth animation */
  will-change: transform;

  /* Apply transform via CSS vars — JS writes the numbers,
     CSS handles the units and the easing */
  transform: translate3d(
    calc(var(--hfx-x, 0) * 1px),
    calc(var(--hfx-y, 0) * 1px),
    0
  ) scale(var(--hfx-scale, 1));

  /* Smooth reset transition when pointer leaves */
  transition: transform 0.65s cubic-bezier(0.23, 1, 0.32, 1);
}

/* While actively tracking, use a fast/direct response */
[data-hover-fx].is-tracking .hover-fx-target {
  transition: transform 0.06s linear;
}

/* ── 4. Optional: CSS-only fallback for hover ───────────── */
/* If JS is unavailable, provide a minimal hover state.
   Only applies when .hover-fx-target is NOT being driven by JS
   (i.e. --hfx-x is unset) */
@media (hover: hover) and (prefers-reduced-motion: no-preference) {
  [data-hover-fx]:hover .hover-fx-target {
    /* A gentle static offset as pure-CSS fallback.
       JS overrides this via the CSS vars above. */
    transform: translate3d(3px, -3px, 0);
    transition: transform 0.35s cubic-bezier(0.23, 1, 0.32, 1);
  }
  /* Once JS is active (is-tracking), remove the static fallback */
  [data-hover-fx].is-tracking:hover .hover-fx-target {
    transform: translate3d(
      calc(var(--hfx-x, 0) * 1px),
      calc(var(--hfx-y, 0) * 1px),
      0
    ) scale(var(--hfx-scale, 1));
  }
}

/* ── 5. Elementor widget container compatibility ────────── */
/* Prevent Elementor's default overflow settings from clipping */
.elementor-widget-wrap > [data-hover-fx],
.elementor-widget-container > [data-hover-fx] {
  overflow: hidden;
}
/* ============================================================ */

Section 08

JavaScript Code

Add this to: Elementor → Advanced → Custom JS, or via a Code Snippets plugin (in footer), or enqueue via functions.php.

hover-fx-system.js 
/**
 * HOVER FX SYSTEM v1.0
 * Pointer-follow image translate for WordPress + Elementor
 *
 * Usage:
 *   Add data-hover-fx to any card wrapper.
 *   Add class hover-fx-target to the image inside it.
 *
 * Config attributes (all optional, on the host element):
 *   data-hover-fx-intensity="8"     — max px translation (default 8)
 *   data-hover-fx-scale="1"         — image scale on hover (default 1)
 *   data-hover-fx-target=".my-img"  — custom child selector
 *
 * No dependencies. No jQuery. No GSAP.
 */

(function () {
  'use strict';

  /* ── Guards ───────────────────────────────────────────── */
  // Skip entirely on reduced-motion preference
  if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) return;
  // Skip on touch / hover-incapable devices
  if (window.matchMedia('(hover: none)').matches) return;

  /* ── Defaults ─────────────────────────────────────────── */
  var DEFAULTS = {
    intensity: 8,
    scale: 1,
    targetClass: 'hover-fx-target'
  };

  /* ── Parse config from a host element ─────────────────── */
  function parseConfig(host) {
    return {
      intensity: parseFloat(host.dataset.hoverFxIntensity) || DEFAULTS.intensity,
      scale:     parseFloat(host.dataset.hoverFxScale)     || DEFAULTS.scale,
      selector:  host.dataset.hoverFxTarget || ('.' + DEFAULTS.targetClass)
    };
  }

  /* ── Initialise a single host element ─────────────────── */
  function initHost(host) {
    // Guard against double-init (important for Elementor re-renders)
    if (host._hfxDone) return;
    host._hfxDone = true;

    var cfg    = parseConfig(host);
    var target = host.querySelector(cfg.selector);
    if (!target) return; // no target found — skip silently

    var rafId = null;

    /* ── Pointer move handler ── */
    function onMove(e) {
      // Cancel any pending frame before scheduling a new one
      if (rafId) cancelAnimationFrame(rafId);

      rafId = requestAnimationFrame(function () {
        var rect = host.getBoundingClientRect();

        // Normalize cursor position: -1 (left/top) to +1 (right/bottom)
        var normX = ((e.clientX - rect.left)  / rect.width  - 0.5) * 2;
        var normY = ((e.clientY - rect.top)   / rect.height - 0.5) * 2;

        // Clamp to prevent overshoot on rapid movement at edges
        normX = Math.max(-1, Math.min(1, normX));
        normY = Math.max(-1, Math.min(1, normY));

        // Write CSS vars — CSS handles units and compositing
        target.style.setProperty('--hfx-x', (normX * cfg.intensity).toFixed(3));
        target.style.setProperty('--hfx-y', (normY * cfg.intensity).toFixed(3));
        target.style.setProperty('--hfx-scale', cfg.scale);

        rafId = null;
      });
    }

    /* ── Pointer enter handler ── */
    function onEnter() {
      host.classList.add('is-tracking');
    }

    /* ── Pointer leave handler ── */
    function onLeave() {
      host.classList.remove('is-tracking');
      if (rafId) { cancelAnimationFrame(rafId); rafId = null; }

      // Reset to origin — CSS transition handles the smooth ease-out
      target.style.setProperty('--hfx-x', '0');
      target.style.setProperty('--hfx-y', '0');
      target.style.setProperty('--hfx-scale', '1');
    }

    // Attach listeners — passive: true ensures no scroll interference
    host.addEventListener('pointermove',  onMove,   { passive: true });
    host.addEventListener('pointerenter', onEnter,  { passive: true });
    host.addEventListener('pointerleave', onLeave,  { passive: true });

    // Expose cleanup for potential future use
    host._hfxDestroy = function () {
      host.removeEventListener('pointermove',  onMove);
      host.removeEventListener('pointerenter', onEnter);
      host.removeEventListener('pointerleave', onLeave);
      host._hfxDone = false;
      delete host._hfxDestroy;
    };
  }

  /* ── Scan the DOM for all host elements ─────────────────── */
  function initAll() {
    document.querySelectorAll('[data-hover-fx]').forEach(initHost);
  }

  /* ── MutationObserver: handle Elementor dynamic rendering ── */
  var debounceTimer;
  var observer = new MutationObserver(function (mutations) {
    var hasNewNodes = mutations.some(function (m) {
      return m.addedNodes.length > 0;
    });
    if (!hasNewNodes) return;

    // Debounce: wait for burst of mutations to settle
    clearTimeout(debounceTimer);
    debounceTimer = setTimeout(initAll, 150);
  });

  observer.observe(document.body, { childList: true, subtree: true });

  /* ── Bootstrap ──────────────────────────────────────────── */
  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', initAll);
  } else {
    initAll();
  }

  // Elementor editor / frontend hook
  if (typeof window.elementorFrontend !== 'undefined') {
    window.elementorFrontend.hooks.addAction(
      'frontend/element_ready/global',
      initAll
    );
  }
  window.addEventListener('elementor/frontend/init', function () {
    if (window.elementorFrontend && window.elementorFrontend.hooks) {
      window.elementorFrontend.hooks.addAction(
        'frontend/element_ready/global',
        initAll
      );
    }
  });

})();

Section 09

PHP Integration (Optional)

If you prefer to manage this via functions.php or a site-specific plugin rather than Elementor's Custom JS panel, use this snippet. This is the safest WordPress-native method.

functions.php snippet 
<?php
/**
 * Enqueue Hover FX System — CSS + JS
 *
 * Place in your child theme's functions.php
 * OR in a site-specific plugin.
 *
 * Assumes hover-fx-system.css and hover-fx-system.js
 * live in /wp-content/themes/your-child-theme/assets/
 */

add_action( 'wp_enqueue_scripts', 'hfx_enqueue_assets' );

function hfx_enqueue_assets() {
    $theme_uri = get_stylesheet_directory_uri();
    $version   = '1.0.0';

    // Enqueue CSS in head
    wp_enqueue_style(
        'hover-fx-system',
        $theme_uri . '/assets/hover-fx-system.css',
        array(),    // no dependencies
        $version
    );

    // Enqueue JS in footer (true = footer), after jQuery if present
    wp_enqueue_script(
        'hover-fx-system',
        $theme_uri . '/assets/hover-fx-system.js',
        array(),    // no jQuery dependency — pure vanilla
        $version,
        true        // load in footer
    );
}
?>

When to Use PHP vs Elementor Custom JS

Use PHP if you want version control, browser caching via WordPress's asset versioning, and centralised control. Use Elementor Custom JS if you want a no-code deployment path for a single site that non-developers manage. Both approaches are safe.

Performance Notes

  • will-change: transform is set only on .hover-fx-target — not globally
  • All animation uses transform: translate3d() — GPU-composited, no reflow
  • Pointer events are handled with passive: true — does not block scroll
  • One requestAnimationFrame per pointermove event — not per frame (more efficient)
  • MutationObserver is debounced (150ms) to avoid storm conditions during re-render
  • No global mousemove on document — each listener lives on its own card

Section 11

Non-Technical Elementor User Guide

Written for content editors and site managers who use Elementor but do not write code.

You will not need to write any code yourself. You will copy and paste two blocks of code in two specific places in your WordPress dashboard, and then apply the effect using Elementor's visual editor.

1. What This Hover Effect Does

When someone moves their mouse cursor over a card on your website — for example a testimonial card with a photo — the photo gently moves in the direction of the cursor. When the cursor leaves, the photo smoothly returns to its original position. This creates a sense of depth and polish that makes your site feel more interactive and premium.

2. Before You Start

Checklist Before Installing

  • You have Elementor installed and active
  • You have a child theme active (strongly recommended to protect your changes on theme updates)
  • You have access to the WordPress admin dashboard
  • You have made a full site backup (always backup before adding code)

3. How to Install the CSS

The CSS controls how the image looks during the animation. Copy the code from Section 7 above, then:

  1. In WordPress admin, go to Appearance → Customize
  2. In the left panel, click Additional CSS at the bottom
  3. Paste the CSS code into the text box
  4. Click Publish in the top left corner

You can also use the Code Snippets plugin (free): Snippets → Add New → CSS snippet, paste the code, and activate it.

4. How to Install the JavaScript

The JavaScript makes the image actually follow your cursor. Copy the code from Section 8 above, then:

  1. In Elementor editor, open any page that uses these cards
  2. Click the hamburger menu icon (☰) in the top-left of the editor
  3. Go to Page Settings → Advanced → Custom JavaScript
  4. Paste the JS code into the bottom box (labelled "Before </body> tag")
  5. Click Update

Alternative (global, works on all pages): Use Code Snippets → Add New → JavaScript (footer) and activate it globally.

5. How to Apply the Effect in Elementor

Now you need to tell each card "use the hover effect". This is done without any code — just through Elementor's settings panels.

Step A — Mark the outer card wrapper:

  1. Click the outer card widget (the whole card, not just the image)
  2. In the left panel, click the Advanced tab
  3. Scroll down to find HTML Attributes (may be labelled "Attributes" in some versions)
  4. In the first field type: data-hover-fx
  5. Leave the value field empty, or type true
  6. Click the + button to confirm

Step B — Mark the image inside the card:

  1. Click the image widget inside the card
  2. In the left panel, click the Advanced tab
  3. Find the CSS Classes field
  4. Type: hover-fx-target
  5. Click Update to save the page
  6. Open the live page and move your mouse over the card — the image should follow your cursor

How You Know It Worked

Open the live page (not the editor). Move your mouse slowly over a card with the effect applied. The image inside should move gently in the direction of your cursor. When you move the mouse away, the image should smoothly return to its original position.

6. How to Change the Intensity Safely

Intensity controls how far the image moves. The default is 8 pixels, which is subtle and refined. To change it:

  1. Click the outer card wrapper in Elementor
  2. Go to Advanced → HTML Attributes
  3. Add a new attribute: key = data-hover-fx-intensity, value = a number
  4. Try 6 for very subtle, 10 for noticeable, 14 for strong
  5. Save and preview to check the result

7. How to Remove the Effect from One Element

  1. Click the outer card wrapper in Elementor
  2. Go to Advanced → HTML Attributes
  3. Find the data-hover-fx attribute row
  4. Click the × button next to it to delete it
  5. Save the page — the effect is now gone from this card only

8. What to Do If It Does Not Work

Troubleshooting Checklist

  1. Make sure both the CSS AND the JavaScript are installed
  2. Check that the outer wrapper has data-hover-fx attribute
  3. Check that the image has class hover-fx-target (no typos, no extra spaces)
  4. Open browser DevTools (F12) → Console tab. Look for red error messages
  5. Check if you are testing on a touchscreen laptop — the effect is disabled on touch devices by design
  6. Try clearing your browser cache with Ctrl+Shift+R (or Cmd+Shift+R on Mac)

9. How to Disable It on Mobile

The effect is already automatically disabled on touch/mobile devices — no action needed. On phones and tablets, users use their fingers (not a mouse cursor), so the effect would not make sense. The cards still look completely normal on mobile.

10. How to Completely Uninstall

  1. Remove the CSS you pasted in Customizer → Additional CSS
  2. Remove or deactivate the JavaScript snippet from Code Snippets, OR delete it from Elementor Page Settings → Custom JS
  3. Optionally remove the data-hover-fx attributes from card wrappers in Elementor (the cards will work fine without them even if you leave them)

Section 12

Troubleshooting

Image Does Not Move At All

  • Confirm data-hover-fx exists on the outer wrapper (inspect in DevTools)
  • Confirm .hover-fx-target class exists on the image
  • Check browser console for JS errors
  • Confirm JS snippet is loading — in DevTools → Sources, search for hfx
  • Confirm you are not on a touch device or a device with hover: none
  • Confirm prefers-reduced-motion is not enabled in system accessibility settings

Image Moves But Looks Jerky

  • Confirm no other JS is also animating this element (check for conflicts)
  • Ensure will-change: transform is not being overridden by theme CSS
  • Try adding transform-style: flat to the parent if 3D context is being inherited
  • Check if a GPU-consuming background effect (parallax plugin) is running on the same page

Image Is Clipped or Disappears at Card Edges

  • overflow: hidden on the host wrapper is expected and correct — it clips the image overhang
  • If you want the image to overflow outside the card, remove overflow: hidden from [data-hover-fx]
  • Alternatively, reduce intensity so the image does not travel to the edge

Effect Works in Browser But Not After Elementor Save

  • Elementor may cache the page — clear Elementor cache in Elementor → Tools → Regenerate Files
  • Also clear any server-side cache (Elementor Cloud, WP Rocket, LiteSpeed, W3 Total Cache)
  • Hard-refresh the browser: Ctrl+Shift+R / Cmd+Shift+R
  • The MutationObserver should re-initialise after Elementor re-renders, but if not, re-save the page

Conflict With Another Hover Plugin

  • Check if another plugin (e.g. a tilt effect plugin, Elementskit, Unlimited Elements) is also attaching hover transforms to the same elements
  • If so, remove the conflicting plugin's class/attribute from the same element, or target a different child element
  • Use data-hover-fx-target=".specific-img" to target a very specific element and avoid broader selectors

Effect Breaks on Resize or Scroll

  • The system uses getBoundingClientRect() inside the RAF callback — this always reads fresh coordinates
  • No stale position caching is used — resize/scroll should not break the calculation
  • If it does, check if another script is transforming the outer wrapper (which would affect getBoundingClientRect() accuracy)
